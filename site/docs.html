Install docs

Everything a platform owner needs to add Walk With Me to a site and keep it running.

Install in one line (Level 1)

Add this before the closing body tag on every page. The helper appears in the same corner on every page.

<script src="https://YOUR-HOST/widget/walk-with-me.js"
        data-api="https://YOUR-HOST"
        data-lang="am"
        data-mode="normal"
        defer></script>
Script tag attributes
AttributeValuesWhat it does
data-apiURL, or emptyWhere the API runs. Empty means the same site as the page.
data-langen, amStarting language. The learner can switch it.
data-modenormal, simpleSimple mode: short sentences, one step at a time, read aloud.
data-offline-onlytrueNever call the API. Answers come from the built-in course questions only.

The helper works on pages opened from a file, because the offline answers are a script file, not a data request.

REST API (Level 2)

Every feature has an endpoint. Read the interactive reference at /docs or download the OpenAPI document.

Ask a question:

curl -X POST https://YOUR-HOST/v1/chat \
  -H "Content-Type: application/json" \
  -d '{"text": "Which skills do employers ask for?", "lang": "en", "mode": "normal"}'

The answer comes with citations (section title and link), provider and answered_offline. If nothing in the course matches, not_in_course is true and handoff_suggested offers a person.

List jobs with a support filter:

curl "https://YOUR-HOST/v1/jobs?city=Adama&supports=sign_language_interpreter"

Errors always look like this, so you can show them to people as they are:

{"error": {"code": "invalid_phone", "message": "That phone number is not in a format we can text.",
           "fix": "Use a number like 0911 234567, 0711 234567 or +251 911 234567."}}

Jobs as schema.org data (Level 3)

Add format=jsonld to get the job list as schema.org/JobPosting objects. Job boards and search engines can read them. Supports offered are listed in jobBenefits.

curl "https://YOUR-HOST/v1/jobs?format=jsonld"

Telegram and SMS

Telegram

  1. Create a bot with BotFather and copy its token.
  2. Set TELEGRAM_BOT_TOKEN and TELEGRAM_BOT_USERNAME.
  3. For staff notices, add the bot to a staff group and set TELEGRAM_STAFF_CHAT_ID. Staff answer a learner by replying to the bot's message.
  4. On a laptop the bot uses long polling. On a server set TELEGRAM_MODE=webhook and PUBLIC_BASE_URL; the webhook is /v1/telegram/webhook.

Commands: /start, /help, /jobs, /alerts, /accommodation, /stop.

SMS

By default SMS_GATEWAY=mock: nothing is sent, and every message appears in the SMS simulator. To send real messages set SMS_GATEWAY=africastalking with AFRICASTALKING_USERNAME, AFRICASTALKING_API_KEY and, if you have one, AFRICASTALKING_SENDER_ID. Check first that your provider delivers to Ethio Telecom and Safaricom Ethiopia numbers.

Point the provider's inbound webhook at POST /v1/sms/inbound. Learners send HELP, ASK and a question, JOBS driver adama, ALERT driver adama or STOP.

Choosing the AI provider

Set AI_PROVIDER. Whatever you choose, the offline provider is the fallback: if the model fails, is slow (more than 6 seconds) or cites something that was not retrieved, the answer comes from the human-written course questions instead.

AI providers
ValueNeedsNotes
offlineNothingReturns the best matching human-written answer and its source. Always works.
claudeANTHROPIC_API_KEY, ANTHROPIC_MODELCloud model. Best for Amharic.
localLOCAL_LLM_URL, LOCAL_LLM_MODELAny OpenAI-compatible server, such as Ollama. Small local models are weak in Amharic; use it for English.

Other settings: MIN_SCORE (how closely a question must match the course, default 0.35), K_MIN (how many times a question must be asked before the teacher view shows it, default 3), STAFF_TOKEN (staff console and teacher view), PUBLIC_BASE_URL (links in alerts).

Run with Docker Compose

cp .env.example .env      # set STAFF_TOKEN at least
docker compose up         # API, widget and pages on http://localhost:8000
docker compose --profile local-ai up   # also starts Ollama

It works with only AI_PROVIDER=offline. Health check: /healthz.

Privacy and deletion

  • Learners have no accounts. A random session id is kept on their device.
  • Chat text is deleted 7 days after the session starts.
  • A call-back phone number is deleted when the help request ends.
  • Alert subscriptions last until the learner stops them (STOP, /stop or the jobs page).
  • Interview support messages are drafted and returned. They are never stored.
  • The teacher view shows questions only, with no session ids, and only after K_MIN learners asked them.

A learner can delete their session data with DELETE /v1/me?session_id=…. The helper panel offers this too.

Accessibility statement

We aim for WCAG 2.2 level AA on the helper, these pages, the staff console and the teacher view.

Testing with screen readers (NVDA and TalkBack), keyboard only, 200% zoom and sound off is still in progress. Results, including what does not work yet, are in docs/conformance-report.md in the code repository. We do not claim conformance until that report is filled in with real results.

If something does not work for you, press Talk to a person in the helper, or tell the hackathon organisers.
